# testing learnings

Last reviewed: 2026-10-29

## 스캐너는 음성·양성 둘 다 보고, 패턴은 통독으로 모은다

- **Scope:** `app/scripts/**`·작업 폴더 `scripts/` 의 누출·개인 흔적 스캐너, 공개 전 점검
- **Learning:** 패턴이 빈 문자열이 되면 모든 줄에 맞아 양성 대조가 통과한다 — 빈 패턴을 거절하고, 깨끗한 본문 0건(음성)과 심은 표본의 이름 맞는 적중(양성)을 둘 다 본다. 패턴 자체는 캡처·로그를 통독해 실제 꼴(URL 인코딩·대시 치환·쪼개진 계정 이름)을 모아 정한다. 패턴 목록은 통독을 대신하지 못한다.
- **Evidence:** LIFE-704 빈 패턴이 886건을 잡는 동안 양성 대조는 17/17. LIFE-716 통독이 인코딩·분할 꼴을, 리뷰가 패턴 밖 사용자 이름을 찾았다.
- **Disposition:** `.agents/rules/validation.md` 의 양성 대조 줄 — 다시 나면.

## 문서에 든 명령 블록은 문서에서 추출해 돌린다

- **Scope:** `.agents/**`·스킬·매핑 등 명령 코드블록을 담은 절차 문서, task-coordinate §2 빠른 확인
- **Learning:** 문서 일감의 빠른 확인을 문구 대조로만 하면 블록 안 명령의 결함을 못 잡는다. 블록을 문서에서 그대로 추출해 정상·빈 입력·실패 분기를 한 번씩 돌리고, 손으로 옮긴 복제본으로 대신하지 않는다.
- **Evidence:** LIFE-713 에서 결함 셋(갱신 실패 폴백, 최신 파일 하나만 읽는 사용량 명령, 빈 디렉터리에서 `ls -t` 가 현재 디렉터리를 나열)이 모두 명령 실행에서 나왔고, 문구 대조 세 라운드는 그중 둘을 놓쳤다.
- **Disposition:** task-coordinate §2 「빠른 확인」 정의 — 다시 나면.

## 관측을 원인 문장으로 옮기기 전에 대조군

- **Scope:** 규칙·판정 문서에 실측을 근거로 인용하는 자리
- **Learning:** 한 번의 실패 관측을 「X 때문에 Y 였다」로 쓰기 전에, X 만 다른 대조군을 같은 경로로 한 번 돌린다. 못 돌리면 「원인은 가르지 못했다」로 적는다.
- **Evidence:** LIFE-713 에서 지정 모델 부재로 띄운 Codex 가 멈춘 것을 부재 탓으로 적었는데, 카탈로그에 있는 모델도 같은 경로에서 똑같이 멈췄다 — 대조군 한 번이 리뷰 중간 지적 하나를 닫았다. LIFE-711 빈 목록(캐시 칸 null)도 같은 회차 trace 대조로 잡혔다.
- **Disposition:** `.agents/rules/validation.md` 양성 대조 줄 옆 — 다시 나면. (「빈 결과는 양성 대조 뒤에야 근거」와 같은 계열이라 승격 때 합친다)

## 비밀 스캐너 허용은 이력·staged·작업 트리 세 경로에서 확인한다

- **Scope:** `.gitleaksignore`·비밀 스캐너 허용 목록, pre-commit 훅
- **Learning:** `.gitleaksignore` 지문은 commit SHA 를 포함해 이력 스캔에만 맞는다. 같은 줄을 pre-commit(staged)·작업 트리 스캔에서도 허용하려면 HEAD 의 그 줄에 인라인 `gitleaks:allow` 를 따로 단다. 허용 기준은 세 경로를 모두 시험한다.
- **Evidence:** LIFE-716 — 이력 스캔 0건으로 통과한 뒤, 허용한 줄을 고쳐 stage 하자 pre-commit 훅이 막았다.
- **Disposition:** `.gitleaksignore` 머리 주석으로 충분하면 승격 없이 삭제, 다시 나면 task-coordinate §2 예시.

## 「제품을 검사한다」로 분류하기 전에 기본 실행에서 도는지 본다

- **Scope:** 시험 분류·정리 일감, task-coordinate §1 분석
- **Learning:** 환경변수로만 켜지는 시험은 이름과 import 가 제품을 가리켜도 기본 실행(`npm test`)에서는 skip 이라 보호가 0 이다. 분류 전에 기본 실행에서 실제로 돌고 skip 되지 않는지 확인한다.
- **Evidence:** LIFE-717 — 제품 모듈을 import 하는 창 없는 하네스 시험 둘을 제품 검사로 분류했다가 리뷰가 env 없으면 skip 임을 찾았다.
- **Disposition:** 같은 실수 두 번째면 validation.md.

## 새 독자 리허설은 사용자 문맥을 끊고 띄운다

- **Scope:** validation.md 새 독자 리허설, task-coordinate §2 판정 기준
- **Learning:** 리허설 세션은 레포 밖에 뽑은 문서 사본을 cwd 로 띄운다 — 레포 경로에 묶인 사용자 자동 메모리가 실려 「맥락 없음」이 깨진다. 셸이 물려받은 API 키 환경변수는 로그인보다 우선하므로 리허설 자식 프로세스에서만 지우고 띄운다.
- **Evidence:** LIFE-719 — 첫 리허설 두 세션이 엉뚱한 과금 계정으로 답 없이 끝났고(키를 지운 재실행은 정상), 구현 worktree 를 cwd 로 쓰면 개인 메모가 독자에게 실리는 것을 실행 전에 확인했다.
- **Disposition:** validation.md 새 독자 리허설 줄 또는 매핑 『세션 기동』 — 다시 나면.

## 지우는 스크립트 시험은 사유를 단언하고 판별 장치 전부를 변이한다

- **Scope:** `scripts/*-test.sh`·정리·출고 스크립트 시험, 01-criteria 의 변이 양성 대조 항목
- **Learning:** 멈춤 케이스를 「exit≠0·무변경」만으로 판정하면 가드끼리(또는 git 자체 거절과) 겹쳐 한 가드를 지워도 통과한다 — 케이스마다 사유 문구를 단언한다. 변이 대상은 `die` 가 있는 가드만이 아니라 판별 신호·제외 목록·`--force` 없음·lease 처럼 결과를 가르는 줄 전부다. 고침이 새 검사를 더하면 반쯤 끝난 상태(폴더만 사라진 worktree 등) 이어 정리 케이스를 같이 돌린다.
- **Evidence:** LIFE-724 리뷰가 세 라운드 연속 다른 장치에서 「지워도 시험 통과」를 찾았고, 한 수정이 새 검사로 이어 정리를 깨는 회귀를 냈다.
- **Disposition:** 한 번 더 나오면 task-coordinate §2 판정 기준 작성 줄(변이 양성 대조 항목 정의).

## 화면 판별 문자 집합은 관측이 아니라 소스 분기에서 뽑는다

- **Scope:** `app/backend/herdr-detect.patch` 의 manifest 정규식, 화면 감지 판정 기준
- **Learning:** 판별 표지 문자 집합은 실화면 몇 장이 아니라 대상 프로그램 소스의 모든 그리기 분기(모드·effort·비활성)에서 뽑아 근거와 함께 적는다. 관측에 없는 분기가 곧 오탐·누락 자리다.
- **Evidence:** LIFE-626 — 관측으로 잡은 집합이 Ultra effort·bash 모드 프롬프트를 빠뜨려 리뷰 중간 지적이 됐다.
- **Disposition:** task-coordinate §2 감지 일감 기준 줄 또는 reviewer.md 감지 리뷰 초점.

## 사용자 설정 디렉터리 복원 관문은 쓰기 주체·디렉터리 항목까지 본다

- **Scope:** 네이티브 관문의 사용자 데이터 백업·복원·대조, task-coordinate §1·§2
- **Learning:** 분석 때 그 디렉터리의 상주 쓰기 주체(데몬·다른 세션)를 먼저 보고, 복원 범위를 소유별(사람 설정 = 바이트 일치, 관문이 만든 것 = 되돌림, 상주 주체 소유 = 기록만)로 기준에 박는다. 대조는 빈 디렉터리를 포함한 디렉터리 항목까지 세고 심링크는 따라가지 않는다.
- **Evidence:** LIFE-626 — 바이트 복원 통과선이 상주 데몬 탓에 실행 불가임이 최종 관문에서야 드러났고, 파일만 센 대조기가 빈 디렉터리를 놓쳤다.
- **Disposition:** validation.md 「원자료 보관」 사용자 데이터 사본 줄 또는 task-coordinate §2.

## 로컬 날짜 시험은 로컬·UTC 날짜가 갈리는 씨앗을 두 방향 시간대에서

- **Scope:** 시각을 로컬 날짜로 보여 주는 렌더러 모델·컴포넌트 시험
- **Learning:** 씨앗 시각이 기계 시간대에서 로컬·UTC 날짜가 갈릴 때만 UTC 회귀를 가른다. 동·서 양쪽에서 갈리는 순간을 씨앗으로 두고 변이 관문을 방향이 다른 시간대 두 곳에서 돌린다. UTC 기계에서는 못 가른다.
- **Evidence:** LIFE-711 — KST 에서 갈리지 않는 씨앗이라 UTC 변이가 통과했고, 고친 뒤 Seoul·LA 모두에서 잡혔다.
- **Disposition:** 시각 표시 시험 헬퍼 또는 rules — 다시 나면.
