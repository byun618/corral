# testing learnings

Last reviewed: 2026-10-27

## 스캐너의 양성 대조만으로는 살아 있음을 못 보인다

- **Scope:** `app/scripts/**`·작업 폴더 `scripts/` 의 누출·패턴 스캐너
- **Learning:** 패턴이 빈 문자열이 되면 모든 줄에 맞아 양성 대조가 통과한다. 스캐너는 빈 패턴을 거절하고, 깨끗한 본문에서 0건(음성)과 심은 표본에서 이름이 맞는 적중(양성)을 둘 다 확인한다.
- **Evidence:** LIFE-704 누출 스캔이 BSD sed 이스케이프 실패로 빈 패턴이 돼 886건을 잡았고, 그 회차의 양성 대조는 17/17 이었다. 「빈 결과는 양성 대조 뒤에야 근거」의 반대쪽 — 전부 결과도 근거가 아니다.
- **Disposition:** `.agents/rules/validation.md` 의 양성 대조 줄 — 다시 나면.

## 문서에 든 명령 블록은 문서에서 추출해 돌린다

- **Scope:** `.agents/**`·스킬·매핑 등 명령 코드블록을 담은 절차 문서, task-coordinate §2 빠른 확인
- **Learning:** 문서 일감의 빠른 확인을 문구 대조로만 하면 블록 안 명령의 결함을 못 잡는다. 블록을 문서에서 그대로 추출해 정상·빈 입력·실패 분기를 한 번씩 돌리고, 손으로 옮긴 복제본으로 대신하지 않는다.
- **Evidence:** LIFE-713 에서 결함 셋(갱신 실패 폴백, 최신 파일 하나만 읽는 사용량 명령, 빈 디렉터리에서 `ls -t` 가 현재 디렉터리를 나열)이 모두 명령 실행에서 나왔고, 문구 대조 세 라운드는 그중 둘을 놓쳤다.
- **Disposition:** task-coordinate §2 「빠른 확인」 정의 — 다시 나면.

## 관측을 원인 문장으로 옮기기 전에 대조군

- **Scope:** 규칙·판정 문서에 실측을 근거로 인용하는 자리
- **Learning:** 한 번의 실패 관측을 「X 때문에 Y 였다」로 쓰기 전에, X 만 다른 대조군을 같은 경로로 한 번 돌린다. 못 돌리면 「원인은 가르지 못했다」로 적는다.
- **Evidence:** LIFE-713 에서 지정 모델 부재로 띄운 Codex 가 멈춘 것을 부재 탓으로 적었는데, 카탈로그에 있는 모델도 같은 경로에서 똑같이 멈췄다 — 대조군 한 번이 리뷰 중간 지적 하나를 닫았다.
- **Disposition:** `.agents/rules/validation.md` 양성 대조 줄 옆 — 다시 나면. (「빈 결과는 양성 대조 뒤에야 근거」와 같은 계열이라 승격 때 합친다)
