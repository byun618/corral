## 코드 리뷰 일시 중지 — 2026-09-30 사용자 지시

**당분간 코드 리뷰는 Codex(리뷰 ①) 단독이다.** 리뷰 ②(Claude)·③(Grok)은 기동하지 않는다.
재개는 사용자 지시로만 하고, 재개할 때 이 절을 지운다.

- 신규 작업은 `00-start.md` 역할 구성에 ②·③ 을 `일시 중지` 로 기록한다. 재리뷰도 Codex 새 세션 하나다.
- 판정문(verdict.md)에 "Codex 단독 리뷰(2026-09-30 일시 중지)" 를 적는다 — 리뷰어가 줄었다는 사실이 판정 근거에 드러나야 한다.
- 단일 리뷰어라도 원칙은 그대로다: 전원 침묵(= Codex 침묵)을 통과 근거로 쓰지 않는다. 게이트 ① 사용자 확인의 비중이 커진다.
- grok 의 **분석 단계 외부 서치**(AGENTS.md 플로우 1)는 코드 리뷰가 아니므로 이 중지 대상이 아니다.
- 재개 중인 기존 작업은 기록된 구성을 유지한다 — 단, 사용자가 그 작업에도 적용하라고 하면 따른다.

## Codex 사용량 부족 시 자동 전환 — 2026-10-02 사용자 승인

리뷰 라운드마다 Codex 리뷰어를 띄우기 직전에 Codex 주간 사용량을 확인하고, 부족하면 그 라운드를
**Claude(리뷰 ②)·Grok(리뷰 ③) 2자 리뷰**로 자동 전환한다. 위 일시 중지의 예외이며 사용자 재승인은 필요 없다.

- **확인 방법**: 최신 Codex 세션 로그의 마지막 `rate_limits` 를 읽는다.
  ```bash
  f=$(ls -t $(find ~/.codex/sessions -name '*.jsonl') | head -1)
  grep -o '"rate_limits":{.*"plan_type"[^}]*}' "$f" | tail -1
  ```
  `primary.used_percent`(사용률)·`window_minutes`(창)·`resets_at`(초기화, epoch 초)를 본다. 값은 **마지막 Codex
  호출 시점**의 서버 응답이라 그 뒤 다른 기기 사용분은 빠져 있다. 공식 조회 API 가 아니다(codex-cli 0.159.2 기준).
- **임계값 90%**: `used_percent ≥ 90` 이면 전환한다. 리뷰 한 세션이 주간 1~3% 를 쓰고(2026-09-30~10-02 실측
  15세션) 로그 값이 실제보다 낮을 수 있어서 여유를 둔다.
- **확인 실패는 부족이 아니다**: 로그가 없거나 형식이 달라 못 읽으면 Codex 를 그대로 띄운다.
- **라운드 중 소진**: Codex 리뷰가 한도 초과로 끝나면 실패 종료 보고로 받고, 그 라운드를 2자로 다시 띄운다.
- **Grok 도 실패하면 Claude 단독으로 진행한다** (사용자 판단: 멈추거나 리뷰를 건너뛰는 것보다 낫다).
  Claude 리뷰어는 구현자(Opus)와 다른 모델인 Sonnet 이다.
- **복귀**: 라운드마다 다시 판단한다. 사용률이 90% 아래로 내려가면(초기화 뒤) 다음 라운드부터 Codex 로 돌아간다.
- **기록·보고**: 전환한 라운드마다 사용률·측정 시각·초기화 시각·실제 리뷰 구성을 `reviews.md` 해당 라운드 절과
  `verdict.md` 라운드 요약표에 적고, 사용자에게 한 줄로 알린다. 조용한 전환이 아니다.

## Grok 한도 소진 시 외부 서치 생략 — 2026-10-02 사용자 승인

분석 단계(AGENTS.md 플로우 1)의 grok 외부 서치는 Grok 주간 한도가 소진됐으면 **생략하고 코디 검색만으로 진행한다.**
「grok 이 없으면 차단 사유로 보고」(task-coordinate §0)의 예외이며 사용자 재승인은 필요 없다.

- **확인 방법**: grok 세션을 띄워 기동 배너의 `Weekly limit left: N%` 를 『화면 관측』으로 읽고, **입력 없이** 닫는다
  (LIFE-478 `raw/coordinator/c41-grok-probe-*` 방식). `grok_status` 는 인증만 보여 주고 한도를 주지 않는다.
- **0% 면 생략**한다. 배너를 못 읽거나 형식이 다르면 소진으로 보지 않고 평소대로 서치를 맡긴다. 서치 도중 한도 초과로
  끝나면 그때까지 받은 답만 쓰고 나머지는 생략으로 기록한다.
- **대체**: 코디 웹 검색에 더해 `gh` 로 대상 저장소 이슈·PR 을 직접 찾는다(Grok 이 주로 메우던 이슈 트래커·버전 변화 쪽).
  다른 도구로 Grok 역할을 흉내 내지 않는다 — 대조가 빠진 것은 빠진 대로 둔다.
- **기록·보고**: `00-analysis.md` 서치 표에 「Grok 미기동 — 주간 한도 0%(관측 시각)」를 적고, 교차 대조 칸은 **공백**으로 둔다.
  게이트 ⓪ 보고에 한 줄로 알린다. 코드 리뷰 쪽 Grok 실패 처리는 위 「Codex 사용량 부족 시 자동 전환」을 따른다.

## 모델·effort 선택 근거

- **2026-09-29 전환 전제**: Opus 5.5·Sonnet 5.5 가 Fable 5.1 보다 지능이 높다는 외부 평을 받아들여
  실측 없이 전환했다. 전제가 틀린 신호(리뷰 라운드 증가, 판정 번복)가 보이면 이 파일부터 되돌린다.
- **코디네이터 = Opus 5.5**: 판단이 가장 비싼 자리라 가장 높은 모델을 둔다. 캐시 읽기 단가도
  불리하지 않다 — Opus 5.5 는 입력 $4 × 캐시 읽기 5% = $0.20/MTok, Fable 5.1 은 $10 × 2.5%
  = $0.25/MTok (2026-09-29 공식 모델 개요 기준). Fable 의 별도 주간 천장에서도 벗어난다.
  effort 는 high — API 기본값이 medium 이라 명시하지 않으면 내려간다.
- **구현 = Opus 5.5 medium** (2026-09-30 사용자 지시, high → medium): 구현 품질이 리뷰 라운드 수를 정한다.
  effort 는 기동 플래그로 **명시**한다(`--effort medium`) — 기본값에 맡기지 않는다. 리뷰 라운드가 늘면 high 로 되돌리는 신호로 본다.
- **advisor 기본 해제**: advisor 는 실행 모델과 등급 차가 있을 때만 발동한다(LIFE-394 실측:
  Fable 코디 0회, Opus 5 워커 23회). Opus 5.5 위의 등급이 없으므로 걸 대상이 없다.
- **코드 리뷰 ② = Sonnet 5.5**: 구현자와 다른 모델로 리뷰어 3자의 모델 다양성을 올린다 — 같은
  모델은 같은 결함을 함께 놓친다(LIFE-394 에서 3자가 모두 놓친 높음 결함이 있었다).
- **본체 세션 = Sonnet 5.5**: 시작·마무리는 브랜치·worktree·머지·정리 같은 기계적 절차다.
- **Codex 구현 = high**: 벤더 가이드가 에이전트 코딩에 지정한 대역이 medium~high 다. xhigh 는
  "평가로 이득이 확인될 때만"이고 코딩 이득 수치가 공개되어 있지 않다. effort 를 올리면
  통과율은 정체하고 동시성·I/O 계열의 미묘한 결함 비중이 오른다.
- **코드 리뷰 Codex = xhigh**: 벤더 가이드가 xhigh 의 예시 용도로 보안·코드 리뷰를 든다.
  구현(high)과 리뷰(xhigh)의 등급을 벌려 두면 높은 effort 가 만드는 미묘한 결함을 더 깊은
  리뷰가 받는다.

## 운영 규칙

- **effort·모델은 기동 시 반드시 명시한다.** 환경 기본이 medium 이라 플래그가 없으면 조용히
  내려간다. 기동 후 세션 중간에 바꾸지 않는다 — 프롬프트 캐시가 깨져 입력 비용이 수십 배로 뛴다.
- **Codex 워커는 모델·effort 를 킥오프에 명시한다.** 위임 경로는 지정이 없으면 모델·effort 를
  넘기지 않고 세션 기본을 탄다. "Codex 에 맡겼으니 Astra high 일 것"은 성립하지 않는다.
- **Codex 워커는 대기 예산을 넉넉히 잡는다.** 같은 과제에서 Claude 보다 느리고 타임아웃이 잦다.
- 모델은 전체 식별자(`claude-opus-5-5`·`claude-sonnet-5-5`)로 요청한다. 전체 식별자는 고정 스냅샷이라
  `claude-opus-5` 가 5.5 로 올라가지 않는다. 별칭(`opus`·`sonnet`)은 제공자별 권장 버전으로 바뀌어
  버전 고정이 아니다 — 새 모델이 나오면 이 파일의 식별자를 직접 올린다. 시작 시 요청한 식별자와 실제 해석된 모델을
  구분해 기록한다. 확인 불가를 성공으로 쓰지 않는다.
- advisor 는 기본 해제다. 명시 변경으로 켤 때는 `claude --advisor <모델>` 로 켜고, 별도 effort·호출
  횟수 옵션을 가정하지 않는다. **advisor 는 독립 리뷰어가 아니다** — 조언 자체는 지적이 아니며
  지적은 diff 에서 재현 가능해야 등록한다.
- 시작 시 전체 역할·모델·effort·구현 방식·명시 변경을 `00-start.md` 에 복사한다.
  `02-kickoff.md` 는 그 기록을 따른다. 재개는 저장된 구성을 유지하고 새 기본값을 소급하지 않는다.
- 모델 미지원·사용량 소진 시 대체 모델을 임의 기동하지 않는다. 해당 단계와 가능한 대안을 보고한다.
- 세 사용자 승인(킥오프·채택·출고)을 유지한다.

- 기본은 단독이다. 코디네이터 추천 또는 사용자 요구로 발동하며 **발동 근거를 킥오프에 명시한다**:
  ① 접근이 갈리고 문서로 우열이 안 날 때 ② 되돌리기 비싼 변경 ③ 터미널·에이전트 제어 계층
  ④ Claude 주간 쿼터가 임계에 근접했을 때
- 경쟁 페어는 Claude `claude-opus-5-5` medium ∥ Codex `gpt-6-astra` high 다. 명시한 구현자 모델이
  있으면 그 지정이 우선한다. Claude 쪽 워커 수는 단독일 때와 같으므로 경쟁이 Claude 쿼터를
  늘리지 않는다 — Codex 는 별도 구독이다.

- 자기 구현 브랜치에 대한 리뷰는 지적 수집에는 쓰되 **승자 판정 근거로 세지 않는다.**
