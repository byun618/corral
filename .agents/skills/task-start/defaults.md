## 모델·effort 선택 근거

- **2026-09-29 전환 전제**: Opus 5.5·Sonnet 5.5 가 Fable 5.1 보다 지능이 높다는 외부 평을 받아들여
  실측 없이 전환했다. 전제가 틀린 신호(리뷰 라운드 증가, 판정 번복)가 보이면 이 파일부터 되돌린다.
- **코디네이터 = Opus 5.5**: 판단이 가장 비싼 자리라 가장 높은 모델을 둔다. 캐시 읽기 단가도
  불리하지 않다 — Opus 5.5 는 입력 $4 × 캐시 읽기 5% = $0.20/MTok, Fable 5.1 은 $10 × 2.5%
  = $0.25/MTok (2026-09-29 공식 모델 개요 기준). Fable 의 별도 주간 천장에서도 벗어난다.
  effort 는 high — API 기본값이 medium 이라 명시하지 않으면 내려간다.
- **구현 = Opus 5.5**: 구현 품질이 리뷰 라운드 수를 정한다.
- **advisor 기본 해제**: advisor 는 실행 모델과 등급 차가 있을 때만 발동한다(LIFE-394 실측:
  Fable 코디 0회, Opus 5 워커 23회). Opus 5.5 위의 등급이 없으므로 걸 대상이 없다.
- **코드 리뷰 ② = Sonnet 5.5**: 구현자와 다른 모델로 리뷰어 3자의 모델 다양성을 올린다 — 같은
  모델은 같은 결함을 함께 놓친다(LIFE-394 에서 3자가 모두 놓친 높음 결함이 있었다).
- **본체 세션 = Sonnet 5.5**: 시작·마무리는 브랜치·worktree·머지·정리 같은 기계적 절차다.
- **Codex 구현 = high**: 벤더 가이드가 에이전트 코딩에 지정한 대역이 medium~high 다. xhigh 는
  "평가로 이득이 확인될 때만"이고 코딩 이득 수치가 공개되어 있지 않다. effort 를 올리면
  통과율은 정체하고 동시성·I/O 계열의 미묘한 결함 비중이 오른다.
- **코드 리뷰 Codex = xhigh**: 벤더 가이드가 xhigh 의 예시 용도로 보안·코드 리뷰를 든다.
  구현(high)과 리뷰(xhigh)의 등급을 벌려 두면 높은 effort 가 만드는 미묘한 결함을 더 깊은
  리뷰가 받는다.

## 운영 규칙

- **effort·모델은 기동 시 반드시 명시한다.** 환경 기본이 medium 이라 플래그가 없으면 조용히
  내려간다. 기동 후 세션 중간에 바꾸지 않는다 — 프롬프트 캐시가 깨져 입력 비용이 수십 배로 뛴다.
- **Codex 워커는 모델·effort 를 킥오프에 명시한다.** 위임 경로는 지정이 없으면 모델·effort 를
  넘기지 않고 세션 기본을 탄다. "Codex 에 맡겼으니 Astra high 일 것"은 성립하지 않는다.
- **Codex 워커는 대기 예산을 넉넉히 잡는다.** 같은 과제에서 Claude 보다 느리고 타임아웃이 잦다.
- 모델은 전체 식별자(`claude-opus-5-5`·`claude-sonnet-5-5`)로 요청한다. 전체 식별자는 고정 스냅샷이라
  `claude-opus-5` 가 5.5 로 올라가지 않는다. 별칭(`opus`·`sonnet`)은 제공자별 권장 버전으로 바뀌어
  버전 고정이 아니다 — 새 모델이 나오면 이 파일의 식별자를 직접 올린다. 시작 시 요청한 식별자와 실제 해석된 모델을
  구분해 기록한다. 확인 불가를 성공으로 쓰지 않는다.
- advisor 는 기본 해제다. 명시 변경으로 켤 때는 `claude --advisor <모델>` 로 켜고, 별도 effort·호출
  횟수 옵션을 가정하지 않는다. **advisor 는 독립 리뷰어가 아니다** — 조언 자체는 지적이 아니며
  지적은 diff 에서 재현 가능해야 등록한다.
- 시작 시 전체 역할·모델·effort·구현 방식·명시 변경을 `00-start.md` 에 복사한다.
  `02-kickoff.md` 는 그 기록을 따른다. 재개는 저장된 구성을 유지하고 새 기본값을 소급하지 않는다.
- 모델 미지원·사용량 소진 시 대체 모델을 임의 기동하지 않는다. 해당 단계와 가능한 대안을 보고한다.
- 세 사용자 승인(킥오프·채택·출고)을 유지한다.

## 경쟁 구현 (옵션)

- 기본은 단독이다. 코디네이터 추천 또는 사용자 요구로 발동하며 **발동 근거를 킥오프에 명시한다**:
  ① 접근이 갈리고 문서로 우열이 안 날 때 ② 되돌리기 비싼 변경 ③ 터미널·에이전트 제어 계층
  ④ Claude 주간 쿼터가 임계에 근접했을 때
- 경쟁 페어는 Claude `claude-opus-5-5` high ∥ Codex `gpt-6-astra` high 다. 명시한 구현자 모델이
  있으면 그 지정이 우선한다. Claude 쪽 워커 수는 단독일 때와 같으므로 경쟁이 Claude 쿼터를
  늘리지 않는다 — Codex 는 별도 구독이다.
- 각 후보는 같은 킥오프·같은 기준을 받고 독립 구현한다. 상대 구현·리뷰·판정을 공유하지 않는다.
- 자기 구현 브랜치에 대한 리뷰는 지적 수집에는 쓰되 **승자 판정 근거로 세지 않는다.**
