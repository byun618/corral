# 작업 시작 기본 구성

2026-09-21 사용자 합의. 신규 작업은 설정 질문 없이 아래 구성으로 시작한다.
역할 기본값의 원본은 이 파일 하나다. 명시한 사용자 변경은 해당 작업에만 적용한다.

| 역할 | 도구·모델 | effort |
| --- | --- | --- |
| 코디네이터 | Claude `claude-fable-5-1` | xhigh |
| 설계·구현 워커 | Claude `opus` | high |
| 워커 advisor | Claude `claude-fable-5-1` | high |
| 설계 리뷰 | Codex `gpt-6-astra` | high |
| 코드 리뷰 | 별도 Codex `gpt-6-astra` | xhigh |
| 보조 코드 리뷰·외부 조사 | Grok | grok-search의 설치 기본값 |

- 기본 구현 방식은 **단독**, 구현 전 설계·독립 설계 리뷰는 필수다. 코디네이터 도구만
  Codex로 지정하면 `gpt-6-astra` xhigh를 사용하고 다른 역할은 그대로 둔다.
- `opus`는 설치 CLI가 제공하는 별칭이다. 시작 시 요청한 식별자와 실제 해석된 모델을
  구분해 기록한다. 다른 모델도 실제 기동 모델·effort를 확인하며 확인 불가를 성공으로 쓰지 않는다.
- advisor effort는 사용자가 별도 지정하지 않은 운영 기본값 high다. advisor는 독립 리뷰어가 아니다.
- 시작 시 전체 역할·모델·effort·구현 방식·명시 변경을 `00-start.md`에 복사한다.
  `02-kickoff.md`는 그 기록을 따른다. 재개는 저장된 구성을 유지하고 새 기본값을 소급하지 않는다.
- 모델 미지원·사용량 소진 시 대체 모델을 임의 기동하지 않는다. 해당 단계와 가능한 대안을 보고한다.
- 사용자가 경쟁 구현을 지정하면 Claude Fable high와 Codex Astra high를 기본 경쟁 페어로 쓴다.
  명시한 구현자 모델이 있으면 그 지정이 우선한다. 각 후보는 별도로 설계·리뷰·구현하며
  서로의 설계를 공유하지 않는다. advisor는 후보별로 분리하고 양 후보를 동시에 조언하지 않는다.
  설계/코드 리뷰 기본값은 위와 같으며 같은 도구의 구현자도 별도 리뷰 세션으로 검토한다.
- 세 사용자 승인(킥오프·채택·출고)을 유지한다. 설계 통과는 코디네이터의 내부 판정이며
  범위·완료 기준 변경이 있을 때만 사용자에게 다시 보고한다.
