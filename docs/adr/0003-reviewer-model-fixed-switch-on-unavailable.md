# 리뷰어 지정 모델은 구독 상태와 무관하게 고정하고, 쓸 수 없는 라운드만 전환한다

## Context and Problem Statement

코드 리뷰 ① 의 지정 모델(Codex 최상위 모델)이 계정 카탈로그에서 사라져 여러 일감의 리뷰가 규칙 밖 선례로 다른 리뷰어에게 넘어갔다. 원인은 모델 폐기가 아니라 구독 등급 하락이었고 재구독 여부는 미정이다(LIFE-713). 지정 모델을 바꿀 것인가, 쓸 수 없을 때의 처리를 규칙으로 둘 것인가.

## Decision Drivers

* 구독 상태는 가역적이다 — 바뀔 때마다 규칙 문서를 고치지 않는다
* 리뷰 ① 모델 선택의 근거(최상위 모델·높은 effort)를 지킨다
* 「대체 모델을 임의 기동하지 않는다」를 유지한다
* 전환은 조용하지 않아야 한다 — 사유·관측값이 판정문에 남는다

## Considered Options

* A — 지정 모델 유지, 「사용 불가」(계정 카탈로그 부재 · 사용량)면 그 라운드를 사전 승인된 리뷰어(Claude·Grok)로 자동 전환
* B — 지금 계정에서 쓸 수 있는 하위 Codex 모델로 지정 식별자 교체
* C — Codex 를 기본 리뷰어에서 뺀다

## Decision Outcome

Chosen option: "A", because 재구독·미구독 두 미래를 문서 수정 없이 덮고(카탈로그에 돌아오면 다음 라운드부터 자동 복귀), 리뷰 ① 의 모델 근거와 대체 금지를 그대로 둔다.

### Consequences

* Good, because 구독이 바뀌어도 규칙 문서를 다시 고치지 않는다
* Good, because 실제로 돌던 구성(Claude 리뷰)이 선례가 아니라 기록되는 규칙이 된다
* Bad, because 구독이 없는 동안 표의 리뷰 ① 은 사실상 매 라운드 전환이다 — 표에 관측 시점을 적어 오독을 막는다
* Bad, because 라운드마다 카탈로그·사용량 확인과 기동 직후 화면 확인이 코디 비용으로 붙는다

### Confirmation

라운드마다 리뷰 기록에 카탈로그 slug 원문·판정·전환 사유가 남는지, 판정문 라운드 요약표에 실제 리뷰 구성이 적히는지(task-coordinate §5·§6).

## Pros and Cons of the Options

### A

* Good, because 가역적인 원인에 가역적으로 대응한다
* Bad, because 카탈로그 갱신 실패 시 내장 목록으로 떨어져 「있음」이 나올 수 있다 — 기동 직후 화면 확인으로 받는다

### B

* Good, because Codex 가 계속 리뷰에 들어간다
* Bad, because 하위 모델에는 리뷰 ① 의 근거가 없고, 무료 등급 사용량이 리뷰 한 세션을 감당하는지 실측이 없다
* Bad, because 재구독하면 다시 고쳐야 한다

### C

* Good, because 단순하다
* Bad, because 재구독 시 재개정, 리뷰어 모델 다양성 근거가 사라진다

## More Information

LIFE-713 (분석·실측), LIFE-703·704 (부재가 처음 드러난 리뷰). 다시 볼 조건: 지정 모델 자체가 폐기되거나, 전환 라운드 비율이 오래 100% 로 남아 사용자가 구독을 접기로 정할 때.
