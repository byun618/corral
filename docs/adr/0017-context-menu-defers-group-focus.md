# 탭 영역 우클릭은 활성만 바로 옮기고, 본문 포커스는 메뉴가 닫힐 때 「우클릭 토큰」 한 규칙으로 준다

## Context and Problem Statement

탭 영역이 여럿일 때 비활성 영역의 탭을 우클릭하면 활성 영역만 옮겨 가고 키보드 포커스는 원래 영역에 남아, 그 상태의 ⌘W 가 보고 있지 않은 영역을 닫았다(LIFE-824 에서 발견, LIFE-825 로 넘김). 「활성 영역 = 포커스 영역」(ADR-0016)을 우클릭에도 지키되, 메뉴가 열려 있는 동안은 포커스를 메뉴 밖 본문으로 옮길 수 없다. 메뉴가 열린 동안 다른 이동(왼쪽 클릭·⌘⌥방향 요청·겹친 우클릭·CLI reveal·메뉴 항목 실행)이 끼어들 때 누가 이기는지를 정해야 했다.

## Decision Drivers

* ⌘W·안 읽음 등 활성 영역 소비자가 사용자가 우클릭한 영역과 어긋나지 않아야 한다
* 메뉴가 열린 동안 포커스를 본문으로 옮기면 메뉴 키 조작(Esc·방향키)이 깨진다
* 메뉴가 열린 동안 사용자가 한 다른 이동은 메뉴 닫힘 포커스에 덮이면 안 된다 — 경로를 하나씩 막는 덧대기가 리뷰 세 라운드 연속 회귀를 냈다(LIFE-825 r2~r4)
* 렌더러만으로 풀고 preload·IPC·배치 저장 형식을 바꾸지 않는다

## Considered Options

* 우클릭 누름 때 바로 본문 포커스까지 옮긴다
* 우클릭은 활성만 옮기고, 메뉴가 닫힐 때 경로마다 「그 사이 다른 이동이 있었나」를 순번으로 막는다
* 우클릭은 활성만 옮기고 「우클릭 토큰」을 세운다 — 메뉴가 닫힐 때 그 토큰이 최신이고 그 사이 **실제로 일어난** 이동(순번 증가·⌘⌥ 이동·reveal)이 없으면 그 영역 본문에 포커스. 진행 중인 ⌘⌥ 요청이 있으면 닫힘 정산을 요청 끝까지 미루고, 메뉴 항목 실행은 미루지 않는다

## Decision Outcome

Chosen option: "우클릭 토큰 한 규칙", because 세우는 입력(우클릭 하나)과 지우는 입력(실제로 일어난 이동)이 한 자리에 모여, 메뉴가 열린 동안의 교차를 경로 목록이 아니라 규칙으로 판정하기 때문이다.

### Consequences

* Good, because 비활성 영역 우클릭 → Esc·바깥 클릭·항목 실행 뒤 활성 영역과 포커스가 같다(⌘W 대상 = 우클릭한 영역)
* Good, because 메뉴가 열린 동안의 다른 이동이 이긴다 — 이동 없이 끝난 요청(가장자리·IPC 거절)은 토큰을 지우지 않는다
* Bad, because 이미 활성인 터미널 영역을 우클릭해도 포커스가 누를 때가 아니라 메뉴가 닫힐 때 온다(눈에 띄지 않는 동작 변화)
* Bad, because 메뉴 안 우클릭이 메뉴를 다시 열지 않는다 — 포털을 거쳐 연 탭으로 올라가 토큰을 덮는 것을 막으려 공용 메뉴 루트에서 contextmenu 전파를 끊었다(카드·탐색기 메뉴도 같다)
* Bad, because VS Code 와 다르다 — VS Code 는 우클릭이 그룹 활성을 바꾸지 않는다

### Confirmation

App 시험(`App.group-layout.test.mjs` 의 우클릭·메뉴 닫힘 갈래 — 겹친 메뉴·가장자리 ⌘⌥·지연 IPC 중 Esc·항목 실행·reveal·메뉴 안 우클릭)과 격리 GUI 관측(우클릭 → 메뉴 생존 → Esc → 본문 포커스·⌘W 대상). 새 포커스 경로를 더하면 이 토큰을 지우는 조건(실제 이동)에 들어가는지 리뷰에서 본다.

## Pros and Cons of the Options

### 누를 때 바로 본문 포커스

* Good, because 단순하고 지연 상태가 없다
* Bad, because 메뉴가 열린 채 본문이 키를 받아 메뉴 키 조작이 깨진다

### 메뉴 닫힘 + 경로별 순번 검사

* Good, because 기존 포커스 순번을 그대로 쓴다
* Bad, because 순번을 안 올리는 경로·이동 없이 끝난 요청·겹친 메뉴가 라운드마다 하나씩 새로 걸렸다(LIFE-825 fix1~fix3)

### 우클릭 토큰 한 규칙

* Good, because 교차를 「토큰이 최신인가·실제 이동이 있었나」 두 질문으로 판정한다
* Bad, because 진행 중 ⌘⌥ 요청이 있으면 닫힘 포커스가 그 응답까지 늦는다(herdr 무응답 동안 지연 — 미확인 한계)

## More Information

LIFE-825(구현·판정), ADR-0016 「활성 영역은 포커스 영역이다」(이 결정은 그 불변식을 우클릭 메뉴로 넓힌다). 남은 예외: macOS Ctrl+클릭은 메뉴가 열리고 활성만 옮는다 · 파일 탭 영역 분할 뒤 body 포커스(base 길) — 둘 다 백로그. 다시 볼 조건: 메뉴가 포커스를 가져가는 방식(포커스 트랩)으로 바뀌거나 VS Code 처럼 우클릭이 활성을 바꾸지 않게 정하면.
